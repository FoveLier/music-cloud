# 云端音乐 · Intent

**Status: approved**

## 一句话

做一个能在手机上发现歌单、点歌播放、看歌词，并把每次播放变成个人听歌报告的仿网易云音乐应用。

## 为什么做

课程前面的案例是功能型页面，数据多半是预置的。这次要做一个数据型应用：歌单、歌曲、播放地址和歌词都来自接口；用户的播放行为又反过来生成第二天的统计页。数据不是背景，而是应用的主角。

## 用户与场景

- 主要用户：在通勤、自习或睡前用手机听歌的学生。
- 典型场景：打开应用 → 在“发现”里挑一个歌单 → 点一首歌 → 在播放页看唱片旋转/歌词 → 回到“听歌报告”看今天听了什么。
- 设备：手机优先；H5 作为过程验证，微信小程序作为课程目标平台。

## 目标

1. 首页展示若干歌单，含封面、名称、歌曲数或描述，点击进入歌单页。
2. 歌单页展示封面、名称、歌曲总数和曲目列表（序号、歌名、歌手、时长、播放入口）。
3. 播放页支持播放/暂停、上一首/下一首、唱片旋转/暂停、歌词模式切换；离开页面销毁播放器。
4. 每次开始播放一首歌，播放次数 +1 并记录播放时间到本地缓存。
5. 统计页用柱状图展示播放次数 Top 10，用折线图展示最近 7 天每天的听歌时长。
6. 请求封装、错误处理、缓存、图表各至少一处；数据取自本地 Meting 服务与本地播放记录。

## 非目标

- 不做登录、注册、支付、会员、评论、私信、关注、动态。
- 不做搜索、歌手页、专辑页、排行榜扩展页、歌单创建/收藏/下载。
- 不做云同步、跨设备、离线音频缓存、语音/OCR/视频。
- 不做非课程要求的第二套主题、国际化、无障碍专项认证。
- 不把个人网易云 Cookie 写入源码、日志、错误提示或提交历史。

## 数据源选择：Meting

- 采用 `@meting/core`（Node.js），由本地 HTTP 服务封装，不由前端直接请求网易云。
- 平台：`netease`；示例歌单：`3778678`（热歌榜）、`3779629`（新歌榜）、`19723756`（飙升榜）。
- 服务端职责：把 Meting 的原始返回归一化为歌单/曲目；短时缓存歌单与歌词；不缓存音频 URL。
- 前端职责：只请求本地服务；播放地址有时效，失败时可重试或换歌。
- 版权与容错：全曲、30 秒试听、无版权空 URL 都要能显示明确提示；演示优先选全曲可用曲目。

## 约束

- uni-app + Vue3 选项式；HBuilderX 编译；H5 和微信开发者工具。
- 页面固定 4 个：首页、歌单页、播放页、统计页；不扩页。
- 图表使用 `qiun-data-charts`（uCharts 封装），不引入第二套图表库。
- 页面内不散写 `uni.request`；统一 `utils/api.js`。
- 缓存统一 `utils/cache.js`；播放记录统一 `utils/stats.js`。
- 播放器实例只在播放页创建，`onUnload` 销毁。
- 所有数据与产物写入 F 盘；不写入 C 盘作业数据。

## 成功标准

- 四个页面能连续走通：首页 → 歌单 → 播放 → 统计。
- 统计页的柱状图/折线图由本机真实播放记录聚合，而不是硬编码。
- 失败路径有用户可读提示：服务未启动、断网、无版权/空播放地址、歌单不存在。
- 缓存命中/过期/弱网降级可观察；刷新后历史仍在。
- `DESIGN.md` 与实现一致，原型稿入库，UI 无明显“AI 味”。
- 审查记录、AI 披露、JOURNEY、提交链完整。

## 风险与假设

- 校园网络访问网易云可能不稳定；服务端缓存与前端降级都要有。
- H5 音频自动播放会被浏览器限制；播放页由用户点击进入，首次 `play()` 放在用户操作后。
- 微信开发者工具需关闭合法域名校验；真机需把 `localhost` 换成电脑内网地址。
- VIP/试听曲目可能只有 30 秒或空 URL；播放器必须容错，不把失败当成播放成功。
- 统计页的“每天听歌时长”按实际播放时长累加（当前音频 `currentTime` 或记录时长），不做后台计时。
